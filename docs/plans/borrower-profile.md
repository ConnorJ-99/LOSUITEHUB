# Borrower Profile & Pre-Qualification (plan, Connor 2026-11-24)

Connor's spec: a loan-level **Borrower Profile** tab under Overview that pulls
everything already on the file into one financial profile, an LO assessment
(AI draft, LO reviewed), a qualification status, and two PDFs (Internal
Borrower Profile, Borrower Pre-Qualification Report / Preliminary Financing
Summary) saved to Docs & Conditions with versions and emailed through GHL.
Sample layout: Connor's "Connor_Watson_Borrower_Profile" PDF (navy header,
4 stat tiles, numbered sections).

## What already exists and gets reused (nothing duplicated)

| Spec item | Where it already lives |
|---|---|
| Borrowers, contact, housing, jobs, other income, assets, debts, REO, declarations | the 1003 (`useApplication`: contacts, addresses, employments, other incomes, `assets`, `liabilities`, `properties` + `property_liens`) |
| Qualifying income, verification | income worksheets (`income_worksheets`, draft / final, sources per figure) |
| Borrower-reported credit | `loan_borrowers.estimated_credit_score`; credit events (`credit_events`); "Pull credit" Workflow step |
| Max purchase price, limited by, cash to close, reserves | Max Approval (`src/lib/calc/maxApproval.ts`, `src/lib/prequal/maxApproval.ts`) |
| Payment, DTI front/back, LTV | `loanScenarioInput` + the payment/ratio calc the 1003 tab uses |
| Readiness (Not ready / Manual review / Needs documents) | `src/lib/prequal/readiness.ts` |
| Financing scenarios | Scenarios & Estimate (`pricing_scenarios`, Selected estimate) |
| Outstanding documents | Docs & Conditions (`loan_conditions`, `document_requests`) |
| Borrower-reported balances | MyHome My assets (`borrower_assets`), goals |
| LO, processor | `loans.assigned_lo_id`, team (`loan_team_members`) |
| PDF engine, branding, one-page fitting | @react-pdf/renderer, `src/lib/documents/brand.ts`, Prequal Results PDF |
| Saving PDFs, emailing with GHL, Messages log | `loan_documents` + `SendDocumentDialog` + the approval send path |
| AI with a review step | `assistant` function tasks + `ai_runs` |

Source tags on every figure: Borrower-reported (prequal/MyHome/application),
Estimated (defaults, Max Approval what-ifs), Document-verified (final income
worksheet, analyzed statement), Credit-report verified (once a mortgage
credit score is recorded), Missing (shown as "Missing", never $0).
Discrepancies: reported vs 1003 assets (already in the Assets card), reported
credit vs credit-report score, application income vs worksheet income.

## Connor's answers (2026-11-24)

- **Qualification status = the pipeline stage** (no new status column). Lead /
  Contacted = Not reviewed or in progress; Pre-Qualified = pre-qualified (the
  existing explicit stage move is the LO confirmation); Pre-Approved and later
  = pre-approved (the letter rules stay as they are). Readiness's result shows
  beside it as a hint ("Additional information required" for Needs
  documents, "Not currently qualified" for Not ready), never stored. Template
  B is a "Pre-Qualification Report" only at Pre-Qualified or later, else a
  "Preliminary Financing Summary"; making a PDF never moves the stage.
- **Keep the Prequal Results PDF** as it is; the new report is separate.
- **Share Internally** = pick a teammate, they get an MPS HQ notification
  linking to the PDF.
- **No credit report score fields**: mortgage credit scores show as Missing;
  only the borrower-reported (estimated) score is used.
